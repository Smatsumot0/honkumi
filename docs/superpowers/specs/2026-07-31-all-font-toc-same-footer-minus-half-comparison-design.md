# 全フォント・目次同サイズ／ノンブル0.5pt小比較PDF 設計

## 目的

アプリ本体の挙動を変更せず、本文、目次内ページ番号、各ページ下部のノンブルのサイズ関係を統一した比較PDFを作成する。本文は9pt、目次内ページ番号は本文と同じ9pt、下部ノンブルは本文より0.5pt小さい8.5ptとし、フォントごとのサイズ補正は適用しない。

## 対象と成果物

- 本文フォント5種類
- ノンブル用フォント8種類
- 合計13 PDF
- 各PDFは既存の全フォントサンプルと同じ本文、用紙、組版、章見出し、目次、奥付を使用する

前回の比較ZIPは残す。新版は次へ出力する。

```text
output/pdf/AllFontSamples-NoAdjust-TOCSame-BodyMinus0.5pt-2026-07-31/
output/pdf/AllFontSamples-NoAdjust-TOCSame-BodyMinus0.5pt-2026-07-31.zip
```

## 生成方式

現在のワークスペースを固定の一時ディレクトリへコピーし、一時コピーだけを変更してDebugビルドする。元ワークスペースのSwiftコード、設定、既存成果物は変更しない。

一時コピーでは次の条件を適用する。

1. 全フォントサンプルの本文サイズを9ptに固定する。
2. 推奨組版によるサイズ上書きを無効にする。
3. 下部ノンブル設定を8.5ptにする。
4. 下部ノンブルの本文フォント別・ノンブル用フォント別サイズ補正を0にする。
5. 目次内ページ番号の実描画サイズを9ptにする。通常の目次数字用`glyphScale`とフォント別補正は、この比較出力に限って適用しない。
6. フォントの選択、本文中の約物・長音補正、行送り、文字送り、配置は維持する。

## ポータブル描画対策

前回の比較生成で、選択フォントに存在しない縦組み字形をQuartzの未解決フォント資源へ渡すと、別のPDFレンダラーで目次リーダーや約物が欠けることが判明した。新版の一時コピーでも、サイズや位置を変えずに次の対策を適用する。

- 目次リーダーは本文5フォントすべてが持つU+30FBを使用する。
- 選択フォントが描画対象字形を持たない場合だけ、同じポイントサイズのしっぽり明朝へフォールバックする。

これらは比較用一時ソースに限定し、アプリ本体へ反映しない。

## 検証

- NFC正規化後のファイル名が期待する13件と完全一致すること。
- 各PDFが11ページで、合計143ページであること。
- PDF内部の文字行列で、本文9pt、下部ノンブル8.5pt、目次内ページ番号9ptを確認すること。
- 各ページに下部ノンブルが1件あり、選択した本文フォントまたはノンブル用フォントで描画されていること。
- 各PDFの目次に6件のページ番号があり、選択したノンブル書体で描画されていること。
- すべてのフォント資源が埋め込み・サブセット化され、未解決フォント資源がないこと。
- 143ページをPopplerで画像化し、レンダーエラー、文字欠け、重なり、クリッピングがないこと。
- 全13件の目次、本文、章見出し、奥付、下部ノンブルを目視確認すること。
- ZIPはUTF-8ファイル名フラグを持ち、13 PDFの展開後ハッシュが元PDFと一致すること。
- 元ワークスペースのアプリ・テスト・プロジェクト設定に追加差分がないこと。

## エラー処理と後片付け

ビルド、Simulator生成、PDF構造検証、全ページレンダリング、ZIP検証のいずれかが失敗した場合は完成扱いにしない。原因を切り分けて再生成し、全条件が通った場合だけ成果物を渡す。

検証完了後は今回専用の一時ソース、DerivedData、レンダー画像、検証スクリプトを削除する。新版の13 PDFとZIP、前回のZIP、ユーザーの既存差分は残す。
