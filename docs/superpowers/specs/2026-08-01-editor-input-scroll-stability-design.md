# エディタ入力時のスクロール安定化設計

## 目的

本文の通常入力、日本語入力の確定、削除、貼り付けで、カーソル周辺の表示が上下へ跳ねたり直前のスクロール位置へ戻ったりしないようにする。自動フォーマットの有効・無効にかかわらず、入力位置は `UITextView` の標準カーソル追従で安定して表示する。

## 現状と原因

`ManuscriptTextEditor.Coordinator` は、確定入力ごとに `applyLiveFormatAndCommit` を呼ぶ。この処理は自動フォーマットによって本文が変化しなかった場合も、入力直後の `contentOffset` を再設定し、必要に応じて独自のカーソル表示処理を実行する。

同じタイミングで `UITextView` もカーソルを表示領域へ保つためにスクロールする。この二つのスクロール制御が競合し、入力のたびに表示位置が戻る、または上下へ跳ねる。自動フォーマットが無効でも `applyLiveFormatAndCommit` 自体は呼ばれるため、設定の有無では解消しない。

## 検討した案

1. 本文が変換されなかった入力ではスクロールへ触れない。
   - 通常入力を UIKit の標準動作へ戻す最小修正。
   - 実際に本文を置換する自動フォーマット時の既存制御は維持できる。
2. キーボード遷移を含む手動スクロール復元をすべて撤去する。
   - 制御は単純になるが、ナビゲーションや局所フォーマット後の表示維持まで変わる。
3. スクロール制御を独立した状態機械へ再設計する。
   - 責務は明確になるが、今回の回帰修正としては範囲が大きい。

今回は1を採用する。

## 実装方針

入力結果を本文へコミットする処理と、局所フォーマットによる置換後の表示調整を分離する。

- `ManuscriptLiveFormatter` の結果が入力直後の本文と同じ場合は、本文と選択範囲だけを Binding へ反映する。
- この経路では `setContentOffset`、独自の選択範囲表示、保存済みスクロール位置の更新を行わない。
- フォーマットによって本文が実際に変化した場合だけ、既存の局所置換、選択範囲補正、表示領域外のカーソル追従を行う。
- 検索、章移動、最下部移動など、明示的なナビゲーションのスクロール動作は変更しない。
- キーボード表示・非表示の復元処理は今回変更せず、通常入力との競合を解消した後も別の再現がある場合に独立して扱う。

条件分岐は UIKit に依存しない純粋な判定として切り出し、単体テストで回帰を固定する。

## テスト

- 自動フォーマットが無効で本文が変わらない入力は、スクロール調整を要求しない。
- 自動フォーマットが有効でも、その入力で本文が変わらなければスクロール調整を要求しない。
- 局所フォーマットで本文が変わった場合は、置換後の表示調整を要求する。
- 既存の `ManuscriptLiveFormatterTests` とエディタ関連テストを実行する。
- Debug Simulatorビルドを行い、通常入力時に本文とカーソルが維持されることを確認する。

## 対象外

- 自動フォーマット規則そのものの変更。
- キーボード遷移時のスクロール設計の全面変更。
- 検索、章移動、ツールバー挿入の仕様変更。
- エディタUIのレイアウトやアニメーション変更。
