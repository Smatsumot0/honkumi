# 共通設定適用ダイアログの高さ修正設計

## 背景

共通設定を作品へ適用するダイアログで、角丸カードの内側に大きな上下余白が表示されている。実機画像では、タイトルから操作ボタンまでの内容量に対してカードだけが画面のほぼ最大高まで伸びている。

直近の小画面対応で、`CommonSettingsReviewDialog`全体へ可変の`frame(maxHeight:)`を付けたことが原因である。この指定は内容が十分収まる画面でもカードを最大高まで拡張するため、既存の20ptの内側余白とは別に大きな空白を生む。

## 要件

- 通常の画面高では、カードの高さを表示内容と上下20ptの内側余白に合わせる。
- カードは画面中央へ表示する。
- 小さい画面、横向き、大きなDynamic Typeなどで内容が収まらない場合だけ、カードを安全領域内の最大高へ制限する。
- 内容が収まらない場合は、カード内部を縦方向へスクロールできるようにする。
- 背景の操作防止、背景のアクセシビリティ非表示、ダイアログのモーダル属性を維持する。
- チェック項目、文言、ボタン動作、初期選択状態は変更しない。

## 採用する方式

`ViewThatFits(in: .vertical)`による通常表示とスクロール表示の切り替えは維持する。ただし、最大高さの制約を角丸カード全体へ常時適用しない。

通常候補は内容の固有高でレイアウトする。内容が利用可能高へ収まらない場合だけ選ばれるスクロール候補に、外側余白とカード内側余白を差し引いた高さ制約を与える。角丸背景と影は、`ViewThatFits`が選択した候補の実際の高さへ追従させる。

これにより、通常時は内容に合うコンパクトなカードになり、小画面時だけ従来どおり安全な最大高とスクロールを使用できる。

## 検討した代替案

### 内容高を計測して明示的なカード高を設定する

`PreferenceKey`などで内容の実寸を取得し、`min(内容高, 最大高)`をカードへ設定する方式。制御は細かいが、計測と再レイアウトの状態管理が増え、Dynamic Type変更時の循環レイアウトやちらつきの可能性があるため採用しない。

### 固定高を設定する

実装は単純だが、端末サイズ、ローカライズ、Dynamic Typeへ追従できず、別の余白や切れを生むため採用しない。

## テスト

- `UIHostingController`で実際の`CommonSettingsReviewDialog`を測定し、十分な画面高ではカードが最大高まで伸びず、固有高に収まることを回帰テストにする。
- 小さい利用可能高ではカードが最大高を超えず、スクロール候補を利用できることを確認する。
- 既存の`CommonSettingsReviewLayout`テストで、安全領域内の最大高計算と中央配置の方針を維持する。
- 共通設定適用、モーダル中の背景操作防止、アクセシビリティに関する既存テストを再実行する。
- Debug、Staging、Releaseの各構成でビルドを確認する。

## 対象範囲

主な変更対象は次の2ファイルと関連テストに限定する。

- `Honkumi/Features/Library/CommonSettingsReviewDialog.swift`
- `HonkumiTests/CommonSettingsReviewPresentationTests.swift`

呼び出し側の`Honkumi/Features/Library/WorkListView.swift`が行う最大高の計算と受け渡しは変更しない。他の設定適用処理、作品データ、PDF生成処理も変更しない。
