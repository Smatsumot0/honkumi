# PDF/X-4 Metadata Synchronization Design

## Goal

Synchronize Honkumi's PDF Document Info Dictionary and XMP metadata for the
metadata fields that already have a value on either side, set the PDF/X-4
identifier correctly, and preserve every layout, drawing, font, page geometry,
and Output Intent behavior.

This change is limited to PDF/X-4 metadata construction, Info Dictionary
normalization, existing Output Intent verification, post-render PDF
finalization, and PDF/X-4 regression tests.

## Current Behavior and Root Cause

`PDFX4ProductionProfile` currently creates the renderer's Document Info and XMP
through separate code paths. XMP fixes `pdf:Producer` to `Honkumi`, while Quartz
adds its own Info `/Producer`, for example
`iOS Version 26.5 (Build 23F77) Quartz PDFContext`. Quartz also adds
`/CreationDate` and `/ModDate`, while the current XMP omits `xmp:ModifyDate` and
uses an independently captured timestamp.

The current XMP also omits the counterparts for the existing Info `/Subject`
and `/Keywords`, and includes
`pdfxid:GTS_PDFXConformance="PDF/X-4"`, which must not be present for this
request. The existing byte-level PDF finalizer normalizes only `/Trapped` and
therefore leaves these differences unchanged.

## Scope Boundaries

The implementation may modify only:

- XMP metadata construction;
- Document Info construction and post-render normalization;
- the metadata parameters passed into the existing PDF finalizer;
- Output Intent inspection and tests, without changing a correct Output Intent;
- PDF/X-4 metadata, structure, font-embedding, encryption, and layout regression
  tests.

The implementation must not modify:

- body, chapter title, table of contents, colophon, or page-number drawing;
- pagination or page-break calculation;
- vertical typesetting;
- character advance, line advance, font size, margins, or font selection;
- MediaBox, CropBox, TrimBox, or BleedBox calculation;
- crop-mark geometry, position, or line width;
- Output Intent or ICC data when the existing value passes all required checks;
- font embedding or subsetting;
- any image or other page-rendering operation.

## Selected Architecture

Create one immutable PDF/X-4 metadata value at the beginning of each PDF export.
Both the renderer's Document Info and the XMP packet are generated from this
same value. The value contains only metadata that the current export already
sets on at least one side:

- title: the existing trimmed document title or `Honkumi` fallback;
- subject: `Print-ready PDF generated by Honkumi`;
- keywords: `print, novel, Honkumi`;
- creator tool: `Honkumi`;
- producer: `Honkumi`;
- creation time and modification time: one export timestamp at whole-second
  precision;
- XMP document and instance identifiers: the existing document UUID and one
  per-export instance UUID.

The metadata value has an optional author field, but this export supplies no
author. Therefore Info `/Author` and XMP `dc:creator` are both omitted. No
colophon value, including author name, circle name, contact information, or URL,
is passed into metadata construction.

Quartz may still replace the Info `/Producer` and date values during rendering.
After rendering, the existing byte-level finalizer receives the same immutable
metadata value and normalizes the mapped Info entries to the authoritative
values used by XMP. The finalizer continues to copy every non-Info indirect
object body byte-for-byte, so the existing XMP stream, Output Intent, ICC
stream, page dictionaries, page resources, content streams, and font streams
remain unchanged during finalization.

The fallback design of copying Quartz's actual producer into XMP is not used.
Both values are normalized to `Honkumi` as requested.

## Metadata Mapping

The canonical metadata value produces the following mappings:

| Document Info | XMP | Rule |
| --- | --- | --- |
| `/Title` | `dc:title` | Same Unicode text |
| `/Author` | `dc:creator` | Both omitted for this export |
| `/Subject` | `dc:description` | Same Unicode text |
| `/Keywords` | `pdf:Keywords` | Same Unicode text |
| `/Creator` | `xmp:CreatorTool` | `Honkumi` on both sides |
| `/Producer` | `pdf:Producer` | `Honkumi` on both sides |
| `/CreationDate` | `xmp:CreateDate` | Same instant |
| `/ModDate` | `xmp:ModifyDate` | Same instant |
| none | `xmp:MetadataDate` | Same value as `xmp:ModifyDate` |

PDF dates use a valid UTC PDF date string. XMP dates use ISO 8601 UTC strings.
The shared timestamp is truncated to whole seconds before either representation
is formatted, which prevents fractional-second differences. The parser tests
compare decoded `Date` values rather than relying only on textual equality.

The XMP packet retains `dc:format=application/pdf`, `xmpMM:DocumentID`, and
`xmpMM:InstanceID`. It contains exactly one
`pdfxid:GTS_PDFXVersion="PDF/X-4"` and contains no
`pdfxid:GTS_PDFXConformance`.

## Components and Data Flow

### `PDFPrintProduction.swift`

Add the immutable metadata value and the PDF/X-4-specific date, PDF-string, and
XMP construction needed by that value. `documentInfo` and `xmpMetadataData` both
consume the value rather than capturing independent values. XMP data creation
is non-optional because all content is constructed as UTF-8.

Do not change `pageGeometry`, the Output Intent dictionary, the Generic CMYK
color space, or ICC extraction.

### `PDFExportService.swift`

Create one metadata value immediately before renderer configuration. Pass it to
both normal and spread-preview XMP construction and to finalization. Do not move
or modify any pagination, page geometry, page loop, or drawing call.

### `PDFX4StructureFinalizer.swift`

Extend the existing finalization boundary to accept the immutable metadata
value. Generalize the top-level Info Dictionary normalizer so it can replace or
insert the mapped entries, encode Unicode safely as PDF strings, and continue to
set `/Trapped /False` as a Name Object. Duplicate mapped keys or a malformed Info
Dictionary cause finalization to fail.

The structural-only finalizer entry point used by synthetic xref tests remains
available. The production file-finalizer path always supplies metadata.

The finalizer does not rewrite the XMP stream. XMP is already canonical because
it was constructed from the same value before rendering, while the finalizer
repairs the Info entries that Quartz can override.

## Error Handling and File Safety

Metadata serialization must not silently omit the XMP packet. A malformed Info
Dictionary, duplicate synchronized key, unreadable rebuilt PDF, unresolved
reference, encryption dictionary, or other existing structural failure aborts
finalization.

The rebuilt PDF is parsed and reopened before atomic replacement. If rendering
or finalization fails, the existing export error path removes the incomplete
output. No partially synchronized PDF is returned.

The implementation adds no owner password, user password, encryption,
permission restriction, JavaScript, form, attachment, optional-content, media,
or external-reference feature.

## Output Intent and Fonts

The current Output Intent and Generic CMYK ICC data are not changed if they pass
the required checks. Tests require:

- exactly one Output Intent;
- `/S /GTS_PDFX`;
- a non-empty `/OutputConditionIdentifier`;
- a non-empty `/RegistryName`;
- at least one non-empty `/Info` or `/OutputCondition` value;
- an embedded `/DestOutputProfile` stream;
- `/N 4` and a valid ICC `acsp` signature.

All used page and nested-resource fonts are traversed. A referenced font without
an embedded FontFile, FontFile2, or FontFile3 descendant fails the test. The
production font selection, embedding, and subsetting code is not modified.

## Automated Tests

### Focused metadata tests

- Verify the canonical Info and XMP values for title, subject, keywords,
  creator, producer, creation time, modification time, and metadata time.
- Parse PDF and XMP date representations to `Date` and compare exact instants.
- Verify `/Author` and `dc:creator` are absent when the metadata author is nil.
- Verify colophon author, circle, contact, and URL values do not appear in Info
  or XMP.
- Verify one PDF/X-4 version identifier and zero conformance identifiers.
- Verify XML escaping and PDF Unicode-string encoding with non-ASCII metadata.
- Verify Quartz-style Info producer and dates are replaced by the canonical
  values during finalization.

### A6, B6, and shinsho crop-mark regression tests

Generate one representative normal PDF for each selectable production size with
crop marks enabled. For each sample, compare the renderer output immediately
before finalization with the finalized output:

- page count;
- every page's MediaBox, CropBox, TrimBox, and BleedBox;
- decoded page content streams;
- extracted text;
- fixed-resolution RGBA pixels for every page.

The comparison must be exactly equal. This proves the finalizer did not change
body position, page breaks, crop marks, page geometry, text extraction, or
appearance. Existing font-size and spread-preview finalization regressions
remain active.

### PDF/X-related structure tests

- Compare all synchronized Info and XMP values on generated PDFs.
- Require Info and XMP producer equality and the exact value `Honkumi`.
- Require creation-date equality and modification/metadata-date equality after
  parsing.
- Check the Output Intent and embedded CMYK ICC criteria above.
- Reject encryption and forbidden interactive or external features.
- Require every used font to be embedded.
- Keep the existing strict xref, trailer, reference, and `/Trapped /False`
  checks.

## External Validation

Run the focused and full XCTest suites, reopen generated PDFs through Core
Graphics and PDFKit, read every object with pypdf in strict mode, inspect
metadata and encryption with Poppler `pdfinfo`, and render pages with Poppler
`pdftoppm`.

The current environment has Poppler and pypdf but does not have Adobe Acrobat
Pro, qpdf, Ghostscript, veraPDF, or another certified PDF/X-4 product preflight.
The completion report must therefore separate the structural and rendering
checks that were completed from the PDF/X-4 product preflight that remains
unverified. It must not claim complete PDF/X-4 conformance without such a
preflight.

## Completion Criteria

- All existing synchronized fields compare equal between Info and XMP.
- Info `/Producer` and XMP `pdf:Producer` both equal `Honkumi`.
- Creation dates represent the same exact instant.
- modification and metadata dates represent the same exact instant.
- Info `/Author` and XMP `dc:creator` are both absent.
- No colophon identity or contact value is added to metadata.
- Exactly one PDF/X-4 version identifier exists and no conformance identifier
  exists.
- Output Intent and embedded CMYK ICC checks pass without production changes.
- Every used font remains embedded.
- PDFs remain unencrypted and unrestricted.
- A6, B6, and shinsho crop-mark comparisons show no page count, box, content,
  extracted-text, or pixel differences.
- Product PDF/X-4 preflight is reported as either executed with its actual result
  or unavailable and unverified.
